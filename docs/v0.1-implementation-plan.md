# v0.1 Implementation Plan

Execution plan for the first shipping version of Bubble Shooter.

This is the practical build order for `v0.1` from [roadmap.md](roadmap.md). Scope is intentionally narrow: a **25-wave playable launch** that can go to the Play Store internal track without dragging future systems into the build.

### Repo layout (current)

Gameplay and shell code live under typed folders, not a flat `scripts/` root:

- `scripts/gameplay/` — `game.gd`, `board_state.gd`, `shot_planner.gd`, `burst_sequence_guard.gd`
- `scripts/audio/` — `sfx_controller.gd`
- `scripts/ui/` — `main_menu.gd`, `splash.gd`, `settings_panel.gd`, `ui_theme.gd`
- `scripts/data/` — `wave_config.gd`, `save_manager.gd`
- `data/` — authored wave table (e.g. `waves_v0_1.json`)
- `tests/unit/` and `tests/helpers/` — GDScript unit suite; `tests/run_tests.gd` for headless runs

### Implementation status (in-tree)

Step numbers match **Build Order** below. This table is the source of truth for what is already landed vs still open.

| Step | Status | Notes |
|------|--------|--------|
| 1 — Wave config + 25 waves | **Done** | `BubbleWaveConfig`, `data/waves_v0_1.json`, spawn/progression wired through board + game |
| 2 — Persistence | **Done** | `BubbleSaveManager`: checkpoint, top runs, settings, onboarding flag |
| 3 — Main menu shell | **Done** | `scenes/main_menu.tscn`, continue / new game / high scores / settings entry points |
| 4 — Pause / resume / back | **Partial** | Pause overlay and HUD wiring in `game.gd`; double-check Android **Back** semantics vs this step’s deliverables |
| 5 — Game over + high score polish | **Partial** | Game-over overlay + recording scores; top-five list from menu — compare UX to this step’s checklist |
| 6 — Onboarding | **Partial** | Splash as entry scene; first-session / first-pop hooks in `game.gd` — refine copy and beats vs spec |
| 7 — Settings + release | **Partial** | Settings panel + export preset excludes `tests/`; keystore, privacy link, release metadata still follow the checklist |

When someone says **“phase 1”** here, they usually mean the first *execution chunk*: wave data + persistence + menu shell (**steps 1–3**). That chunk **is implemented**; steps **4–7** are partly there and need explicit verification/polish, not dismissal as “just refactoring.”

---

## v0.1 Goal

Ship a complete, understandable, restartable mobile game with:

- first 25 waves
- score persistence
- pause / resume
- main menu shell
- onboarding
- release-safe Android build

Not included:

- special bubbles
- board power-ups
- cannon powers
- chapter map
- leaderboard
- full 100-wave progression
- full BGM system

---

## Current Reusable Base

Already in place:

- core bubble shooting loop in `scripts/gameplay/game.gd`
- board logic in `scripts/gameplay/board_state.gd`
- shot planning in `scripts/gameplay/shot_planner.gd`
- procedural gameplay SFX in `scripts/audio/sfx_controller.gd`
- mobile performance pass
- burst sequencing and haptics

Much of the **v0.1 shell** (steps 1–3 and parts of 4–7) is now in the repo; remaining work is mostly verification, polish, and release checklist items—not greenfield gameplay.

---

## Build Order

Implement in this order. Do not jump ahead.

### Step 1 — Wave Config + 25-Wave Progression

Goal:

- replace hardcoded progression assumptions with a data-driven first 25-wave table
- make wave difficulty feel intentional instead of purely emergent

Files:

- implement: `scripts/data/wave_config.gd`
- data: `data/waves_v0_1.json` (or equivalent path used by `BubbleWaveConfig`)
- modify: `scripts/gameplay/board_state.gd`
- modify: `scripts/gameplay/game.gd`

Deliverables:

- `WaveConfig` API for wave number → colors / rows / shots per shift / density
- first 25 waves authored
- next-wave spawn uses config instead of only formula logic
- Wave 1 to Wave 25 feel meaningfully different

Notes:

- do not build all 100 waves yet
- do not add milestone handcrafted boards yet

---

### Step 2 — Persistence

Goal:

- save and restore enough state to support Continue and High Scores

Files:

- implement: `scripts/data/save_manager.gd`
- modify: `scripts/gameplay/game.gd`

Minimum data to persist:

- best 5 runs
- current run checkpoint for Continue
- settings values
- onboarding-complete flag

Recommended runtime files:

- `user://save.cfg`
- `user://scores.cfg`
- `user://settings.cfg`

Deliverables:

- save after wave clear
- save on app background / quit if possible
- Continue resumes last playable checkpoint
- scores survive relaunch

Notes:

- keep persistence simple and local
- do not mix leaderboard logic into this

---

### Step 3 — Main Menu Shell

Goal:

- stop dropping the player directly into gameplay with no context

Files:

- `scenes/main_menu.tscn`
- `scripts/ui/main_menu.gd`
- modify: `project.godot`

Minimum menu actions:

- Continue
- New Game
- High Scores
- Settings

Deliverables:

- app opens to menu
- Continue shown only if valid save exists
- New Game handles overwrite confirmation

Notes:

- keep visuals clean and mobile-first
- no chapter map yet

---

### Step 4 — Pause / Resume + Back Navigation

Goal:

- make the game feel like a proper mobile product

Files:

- modify: `scripts/gameplay/game.gd`
- optional new: `scripts/ui/pause_overlay.gd` (or `scripts/gameplay/pause_overlay.gd`) if logic becomes noisy

Deliverables:

- pause button in HUD
- pause overlay
- resume
- restart run
- back to menu
- Android back button pauses first, exits intentionally second

Notes:

- do not let pause break burst queues or active shot state

---

### Step 5 — Game Over + High Score Polish

Goal:

- turn current game-over state into a real end-of-run screen

Files:

- modify: `scenes/game.tscn`
- modify: `scripts/gameplay/game.gd`
- optional new: `scenes/high_scores.tscn`
- optional new: `scripts/high_scores.gd`

Deliverables:

- score breakdown
- wave reached
- personal-record indicator
- retry
- return to menu
- top 5 score list accessible from main menu

Notes:

- keep animations short
- game-over should not feel punishing, only conclusive

---

### Step 6 — Onboarding

Goal:

- make first session understandable without external explanation

Files:

- `scenes/splash.tscn`
- `scripts/ui/splash.gd`
- modify: `project.godot`
- modify: `scripts/gameplay/game.gd`

Deliverables:

- splash screen
- first-launch intro flow
- Wave 1 extra-readable setup
- one or two contextual tutorial prompts max

Recommended onboarding beats:

1. splash
2. menu
3. first game start
4. "match 3 bubbles"
5. first successful pop acknowledgment
6. normal play

Notes:

- do not build a long tutorial
- keep player playing within seconds

---

### Step 7 — Settings + Release Cleanup

Goal:

- make the build release-safe

Files:

- `scenes/settings_panel.tscn`
- `scripts/ui/settings_panel.gd`
- modify: `export_presets.cfg`
- modify: `project.godot`
- modify: `scripts/gameplay/game.gd`
- modify: `scripts/ui/main_menu.gd`

Deliverables:

- SFX on/off
- volume slider
- FPS hidden in release builds
- app icon / export metadata reviewed
- keystore setup
- privacy policy link ready

Notes:

- BGM setting can exist as disabled / future-safe toggle only if needed
- do not build full music system in `v0.1`

## What To Reuse Instead Of Rebuilding

- keep gameplay in `scripts/gameplay/game.gd` as the active run scene
- keep board rules in `scripts/gameplay/board_state.gd`
- keep shot simulation in `scripts/gameplay/shot_planner.gd`
- keep SFX routing in `scripts/audio/sfx_controller.gd`

Do not create parallel systems for these in `v0.1`.

---

## Non-Goals For v0.1

Explicitly do **not** pull these in:

- Bomb / Rainbow / Stone / Ice / Chaos / Multiplier implementation
- power-up manager
- cannon power selection
- chapter map
- wave path screen
- leaderboard integration
- daily challenge
- dynamic BGM layering

If any of these starts entering the `v0.1` branch, scope has drifted.

---

## Acceptance Checklist

`v0.1` is ready when all of this is true:

- player opens app and understands what to do
- player can finish or fail a 25-wave run cleanly
- game saves enough state for Continue and scores
- pause / resume works reliably
- game over and retry loop feel polished
- release build does not expose debug-only UI
- Android internal testing build is publishable

---

## Recommended Execution Sequence

Practical order for actual implementation:

1. `scripts/data/wave_config.gd` + wave JSON under `data/`
2. `scripts/data/save_manager.gd`
3. `scenes/main_menu.tscn` + `scripts/ui/main_menu.gd`
4. pause / resume in `scripts/gameplay/game.gd`
5. game over + high score polish
6. splash / onboarding (`scripts/ui/splash.gd`, `scenes/splash.tscn`)
7. settings + export cleanup (`scripts/ui/settings_panel.gd`, `export_presets.cfg`)

This is the fastest route to a real `v0.1`.
