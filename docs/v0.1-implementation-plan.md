# v0.1 Implementation Plan

Execution plan for the first shipping version of Bubble Shooter.

This is the practical build order for `v0.1` from [roadmap.md](roadmap.md). Scope is intentionally narrow: a **25-wave playable launch** that can go to the Play Store internal track without dragging future systems into the build.

---

## v0.1 Goal

Ship a complete, understandable, restartable mobile game with:

- first 25 waves
- score persistence
- pause / resume
- main menu shell
- onboarding
- release-safe Android build

Not included:

- special bubbles
- board power-ups
- cannon powers
- chapter map
- leaderboard
- full 100-wave progression
- full BGM system

---

## Current Reusable Base

Already in place:

- core bubble shooting loop in [game.gd](/Users/arautela/bubble-shooter/scripts/game.gd)
- board logic split into [board_state.gd](/Users/arautela/bubble-shooter/scripts/board_state.gd)
- shot planning in [shot_planner.gd](/Users/arautela/bubble-shooter/scripts/shot_planner.gd)
- procedural gameplay SFX in [sfx_controller.gd](/Users/arautela/bubble-shooter/scripts/sfx_controller.gd)
- mobile performance pass
- burst sequencing and haptics

This means `v0.1` is mostly shell, progression config, persistence, and polish work.

---

## Build Order

Implement in this order. Do not jump ahead.

### Step 1 — Wave Config + 25-Wave Progression

Goal:

- replace hardcoded progression assumptions with a data-driven first 25-wave table
- make wave difficulty feel intentional instead of purely emergent

Files:

- new: `scripts/wave_config.gd`
- modify: [board_state.gd](/Users/arautela/bubble-shooter/scripts/board_state.gd)
- modify: [game.gd](/Users/arautela/bubble-shooter/scripts/game.gd)

Deliverables:

- `WaveConfig` API for wave number → colors / rows / shots per shift / density
- first 25 waves authored
- next-wave spawn uses config instead of only formula logic
- Wave 1 to Wave 25 feel meaningfully different

Notes:

- do not build all 100 waves yet
- do not add milestone handcrafted boards yet

---

### Step 2 — Persistence

Goal:

- save and restore enough state to support Continue and High Scores

Files:

- new: `scripts/save_manager.gd`
- modify: [game.gd](/Users/arautela/bubble-shooter/scripts/game.gd)

Minimum data to persist:

- best 5 runs
- current run checkpoint for Continue
- settings values
- onboarding-complete flag

Recommended runtime files:

- `user://save.cfg`
- `user://scores.cfg`
- `user://settings.cfg`

Deliverables:

- save after wave clear
- save on app background / quit if possible
- Continue resumes last playable checkpoint
- scores survive relaunch

Notes:

- keep persistence simple and local
- do not mix leaderboard logic into this

---

### Step 3 — Main Menu Shell

Goal:

- stop dropping the player directly into gameplay with no context

Files:

- new: `scenes/main_menu.tscn`
- new: `scripts/main_menu.gd`
- modify: `project.godot`

Minimum menu actions:

- Continue
- New Game
- High Scores
- Settings

Deliverables:

- app opens to menu
- Continue shown only if valid save exists
- New Game handles overwrite confirmation

Notes:

- keep visuals clean and mobile-first
- no chapter map yet

---

### Step 4 — Pause / Resume + Back Navigation

Goal:

- make the game feel like a proper mobile product

Files:

- modify: [game.gd](/Users/arautela/bubble-shooter/scripts/game.gd)
- optional new: `scripts/pause_overlay.gd` if logic becomes noisy

Deliverables:

- pause button in HUD
- pause overlay
- resume
- restart run
- back to menu
- Android back button pauses first, exits intentionally second

Notes:

- do not let pause break burst queues or active shot state

---

### Step 5 — Game Over + High Score Polish

Goal:

- turn current game-over state into a real end-of-run screen

Files:

- modify: [game.tscn](/Users/arautela/bubble-shooter/scenes/game.tscn)
- modify: [game.gd](/Users/arautela/bubble-shooter/scripts/game.gd)
- optional new: `scenes/high_scores.tscn`
- optional new: `scripts/high_scores.gd`

Deliverables:

- score breakdown
- wave reached
- personal-record indicator
- retry
- return to menu
- top 5 score list accessible from main menu

Notes:

- keep animations short
- game-over should not feel punishing, only conclusive

---

### Step 6 — Onboarding

Goal:

- make first session understandable without external explanation

Files:

- new: `scenes/splash.tscn`
- new: `scripts/splash.gd`
- modify: `project.godot`
- modify: [game.gd](/Users/arautela/bubble-shooter/scripts/game.gd)

Deliverables:

- splash screen
- first-launch intro flow
- Wave 1 extra-readable setup
- one or two contextual tutorial prompts max

Recommended onboarding beats:

1. splash
2. menu
3. first game start
4. "match 3 bubbles"
5. first successful pop acknowledgment
6. normal play

Notes:

- do not build a long tutorial
- keep player playing within seconds

- keystore setup
- privacy policy link ready

Notes:

- BGM setting can exist as disabled / future-safe toggle only if needed
- do not build full music system in `v0.1`

## Non-Goals For v0.1

Explicitly do **not** pull these in:

- Bomb / Rainbow / Stone / Ice / Chaos / Multiplier implementation
- power-up manager
- cannon power selection
- chapter map
- wave path screen
- leaderboard integration
- daily challenge
- dynamic BGM layering

If any of these starts entering the `v0.1` branch, scope has drifted.

---

## Acceptance Checklist

`v0.1` is ready when all of this is true:

- player opens app and understands what to do
- player can finish or fail a 25-wave run cleanly
- game saves enough state for Continue and scores
- pause / resume works reliably
- game over and retry loop feel polished
- release build does not expose debug-only UI
- Android internal testing build is publishable

---

## Recommended Execution Sequence

Practical order for actual implementation:

1. `wave_config.gd`
2. `save_manager.gd`
3. `main_menu.tscn` + `main_menu.gd`
4. pause / resume in [game.gd](/Users/arautela/bubble-shooter/scripts/game.gd)
5. game over + high score polish
6. splash / onboarding
7. settings + export cleanup

This is the fastest route to a real `v0.1`.
